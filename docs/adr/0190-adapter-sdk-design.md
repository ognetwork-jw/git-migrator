# ADR-0190: Adapter SDK design

- Status: accepted (spec updated)
- Date: 2026-10-08
- Task: T-026
- Affects: ADP-010, ADP-011, ADP-012, ADP-013, ADP-014, ADP-050, ADP-060, ADP-061, ADP-070, JOB-041, JOB-043, JOB-044, JOB-045, TST-006, ARC-012, GLO-002

## Context

ADP-060 says what `ProviderHttpClient` does but leaves open: how provider header parsing reaches the quota service without provider vocabulary in the SDK (GLO-002), how the SDK emits telemetry and raw captures when ARC-012 gives it no edge to `observability` or `db`, where `DriverContext.http` comes from, what `EndpointRuntime`, `AdapterContext`, the inventory records and `GitClient` look like, and which hosts the test allowlist accepts. The spec shows the interfaces only partly ("names may gain fields").

## Decision

1. **Neutral hook for provider feedback.** An adapter passes `interpret(response) => Interpretation | undefined`. An `Interpretation` carries neutral numbers: `feedback` (`QuotaFeedback[]`), a limit `signal` (`rate-limited` or `secondary-limit`, with optional `retryAfterSeconds`), cost `adjust` deltas, and an optional error `code` and safe `message`. Adapters read their provider's headers and body (T-032, T-033); the SDK never does. The client fills `observedSince` with the `AcquireResult.at` stamp of the request that produced the response unless the adapter set one (ADR-0180 item 3). Quota-service failures while recording feedback are logged (stripped) and never fail the response.
2. **Limit handling.** HTTP 429 always records a rate-limit block on every bucket of the request, using `Retry-After` (seconds or HTTP date) and `RequestClass.minBlockSeconds`; the adapter may also report a 403 as `rate-limited` or `secondary-limit`. These raise `rate_limited` with `retryAt` (from the quota service's `blockedUntil`) and `retryAfterMs`, and are never retried in process (JOB-044). A denied `acquire` raises `rate_limited` too, with the service's `retryAt`, so the job can call `moveToDelayed(retryAt)`. `AdapterError` gains `retryAt`.
3. **Quota gates are structural.** The client takes `QuotaGate` (what `QuotaService` offers) and `LeaseGate` (what `QuotaLeases` offers), so tests inject fakes and the SDK does not construct the services. The classifier is `(method, path) => RequestClass { endpoint, buckets, bucketLabel?, minBlockSeconds?, concurrency? }`. A request with `concurrency` takes a lease before it acquires quota and releases it in `finally` (JOB-045); a refused lease is `rate_limited` with a 1 s wait and costs no quota.
4. **Every attempt is a request.** Each retry acquires quota again, because each attempt reaches the provider. Redirects count as requests as well but not as retry attempts.
5. **Retries.** Exponential backoff with full jitter (`random() * min(cap, base * 2^(n-1))`, base 1 s, cap 60 s, 5 attempts), for network errors, 408, 500, 502, 503 and 504 (and any other 5xx, mapped `transient`). A request can pass `retry: false` for a write that must not be repeated; the default follows the spec and retries all methods.
6. **Error mapping.** 401 `unauthorized`, 403 `forbidden`, 404 and 410 `not_found`, 409 `conflict`, 451 `blocked_by_provider`, other 4xx `invalid`, 429 `rate_limited`. Messages and `request.url` are built from the stripped URL only; the provider response body is never copied into an error (the adapter may supply a `message`, which is stripped again). A network error's `cause` is replaced by a new `Error` whose text is stripped.
7. **Origin pinning and redirects.** Relative paths resolve under the base URL's path. An absolute URL (a pagination link) must have the base origin; any other origin is refused so credentials cannot leave the Endpoint. Redirects are handled by the client (`redirect: 'manual'`): only GET/HEAD to the same origin, at most 5 hops; writes and cross-origin hops are `invalid`.
8. **Raw capture.** `RawCaptureSink.save(RawCaptureInput) => id` receives a row that is already stripped (ADP-061): authorization/cookie/token headers replaced, URL userinfo and fragment removed, secret-looking query values replaced, secret-looking body fields replaced (string and number values only), the credential values `authorize()` declared in `secrets` removed everywhere, and known token shapes (access tokens, `Bearer`/`Basic`, private key blocks, URL userinfo in text) scrubbed. A text body over 1 MiB is stored as `{ truncated: true, bytes }`. The persistence adapter lives with the job runtime (the SDK has no `db` edge). A sink failure is logged and the request still succeeds; the call then returns no `rawResponseId`. The same strippers back `AdapterError` and log text. This is the SDK's own scrubber, a smaller sibling of the logger's (ADR-0052), because `adapter-sdk` may not import `observability`.
9. **Telemetry.** `ProviderTelemetry { recordRequest(labels, seconds), startSpan? }` is structural. The wiring maps it onto the typed recorders (`gm_provider_requests_total`, `gm_provider_request_duration_seconds`) and the OpenTelemetry tracer. Labels: `provider`, `endpoint` (classifier label), `bucket` (resource group or override), `status` (HTTP status, `network_error`, `denied_<reason>` or `concurrency`). Span end carries only a stripped error text.
10. **Test host allowlist (TST-006).** When the environment is `test` (`options.environment`, default `GM_ENVIRONMENT`), the client refuses every host except `localhost`, `127.0.0.1`, `::1`, the comma-separated `GM_TEST_ALLOWED_HOSTS` and `testAllowedHosts` from the options. The base URL is checked at construction, every request URL (including redirects) at send time. The failure is a non-retryable `invalid` AdapterError.
11. **Where the client comes from.** An adapter builds its `ProviderHttpClient` in `connect` from `AdapterContext` (which extends `ProviderHttpEnvironment`: quota, leases, logger, capture, telemetry, fetch, environment) plus its own classifier, `authorize` and `interpret`, and returns it as `EndpointConnection.http`. The runner builds `DriverContext` from the connection's `http`, so drivers cannot bypass the client. This adds the field `http` to `EndpointConnection` (allowed: "names may gain fields").
12. **Records and refs.** `NamespaceRef { providerId, slug }`, `RepositoryRef { providerId, namespace, slug }`, and the inventory records follow the `Namespace`, `Repository`, `Identity` and `Group` models of the domain schema (provider ids instead of internal ids). `EndpointRuntime { id, baseUrl, config, credential, accountKey }` carries the one credential chosen for the job (JOB-042). `AdapterWarning { code, paths, params }`.
13. **GitClient.** Declared minimally as `lsRemote({ url, credential, signal }) => { refs: { name, sha, peeled? }[], headSymref? }`, which is what adapters need for `git-refs` (FAC-GIT-001). T-027 may add methods; credentials travel as a value, never in the URL (ADP-070, ADP-071).
14. **Coverage.** TST-005 lists no threshold for `adapter-sdk` and `tools/bootstrap.test.ts` pins the list, so none is added. The package is tested to well above the 80% that the other infrastructure packages must reach (measured in the T-026 PR).
15. **Dependencies.** `zod` (the same pinned version as `canonical`) is a dependency for the `configSchema` and `credentialSchema` types. No other external dependency.

## Alternatives

- Parsing `x-ratelimit-*` in the SDK: rejected (GLO-002, and Bitbucket has no such headers).
- Importing `observability` for metrics and redaction: rejected by ARC-012; the structural sink and the small scrubber replace it.
- Passing `DriverContext.http` through the job runtime: rejected; the adapter knows its classifier and credential, so it must build the client.
- Retrying 429 once in process: rejected by ADP-060.
- Following redirects with `fetch` defaults: rejected, because `fetch` would forward the authorization header across origins.

## Consequences

T-032 and T-033 write a classifier, an `authorize`, and an `interpret` per provider, and always capture through `request({ capture: true })` for Facet reads. The job runtime (T-028) supplies the `RawCaptureSink` over the `RawResponse` table, the telemetry mapping, and the quota services. Follow-up for T-028: wire `ProviderTelemetry` onto `MetricRecorders` and the tracer, and implement the sink.

## Round 2 amendments (review findings)

16. **Redaction rules.** A body field is sensitive when its name, lower-cased with separators removed, contains `token`, `secret`, `password`, `passwd`, `passphrase`, `apikey`, `privatekey`, `accesskey`, `credential`, `authorization`, `cookie`, `signature` or `bearer` (so `accessToken` and `refresh_token` match). The whole value is replaced, whatever its type, with no recursion. Form-encoded bodies get the same rule per parameter; other text is scrubbed for secrets and shapes. A captured document over 1 MiB (serialized) is stored as `{ truncated: true, bytes }`.
17. **Declared secrets.** The raw, URL-encoded and base64 forms of each secret are removed, longest first, **before** any shape runs (round 3 reverses the order: a partial shape match must not leave part of a secret behind). Forms: raw, `encodeURIComponent`, `URLSearchParams` serialisation, every-byte percent-encoding, base64 and base64url. A secret under 4 characters cannot be scrubbed without destroying text, so `authorize` results with one are refused as `invalid` (the request is not sent).
18. **Token shapes.** The SDK keeps only generic shapes (`Bearer`, `Basic`, JWT, private key blocks, URL userinfo). Provider-specific prefixes are supplied by the adapter through the client option `tokenShapes`.
19. **Response size.** The body is read as a stream and stops at `maxResponseBytes` (default 32 MiB; a larger declared `Content-Length` fails before reading), failing as `invalid`.
20. **Retry-After.** Only a non-negative integer or an IMF-fixdate, RFC 850 or asctime date is accepted. Integers and dates clamp to 24 h; a past date waits 1 s; anything else is ignored.
21. **URL confinement.** After resolving, the URL must keep the base origin and base path and carry no userinfo (so `../` and same-origin URLs of other APIs are refused), for requests and redirects. A base URL with userinfo is refused at construction. A request class with `concurrency` but no `LeaseGate` is an `invalid` configuration error.
22. **authorize failures** become `AdapterError` (`unauthorized`, or `transient` for network-looking errors) with a stripped message and a sanitized cause.
23. **Test environment.** An explicit environment value decides; when none is set, `NODE_ENV=test` or a Vitest run counts as test. The root Vitest config has no setup files, so this fallback replaces setting `GM_ENVIRONMENT` there.
24. **Pagination.** The default page cap is 1000. Link loops are detected after normalizing (sorted query, no fragment) and the first request URL can seed the set. The `Link` header parser is a single linear scan capped at 64 KiB.

25. **Linear scans (round 3).** Text is cut at 1 MiB before any scan. Built-in shapes are bounded or single-pass (the JWT shape scans token runs once and tests each run with an anchored pattern), and `tokenShapes` documents that adapter regexes must be linear and bounded. Tests run every built-in shape on a 1 MB hostile input.
26. **Key rules.** One word list serves bodies, headers and queries: the substrings above plus `pwd`, `sshkey`, `session`, `jwt` and `assertion`, and the whole-key words `pass`, `auth` and `otp` (so `author` and `footprint` stay visible). Queries also treat `key`, `sig` and `code` as sensitive when they are the whole name. Response-header values are scrubbed too (`Location` and `Link` as URLs). `Basic`/`Bearer` tokens are redacted only when they contain a digit, one of `+/=_-`, or an upper-case letter after the first.
27. **authorize before quota (round 3).** Credentials are obtained before the lease and the quota acquire, so a credential failure spends nothing. Only system error codes (`ECONNRESET`, ...) and undici `fetch failed` count as transient; any other error (including a `TypeError` bug) is `unauthorized` and not retried.
