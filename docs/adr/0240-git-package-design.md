# ADR-0240: Git package design

- Status: accepted (spec updated)
- Date: 2026-10-08
- Task: T-027
- Affects: ADP-070, ADP-071, FAC-GIT-001, FAC-GIT-004, FAC-GIT-005, LIF-040, LIF-042, LIF-044, JOB-015, JOB-041

## Context

The spec fixes the commands (ls-remote, mirror clone, blob scan, LFS, batched push), the quota costs and the `GIT_ASKPASS` mechanism, but leaves open how credentials stay confined, how the package reaches the quota service and the LFS batch API without breaking ARC-012, what `GitClient` looks like beyond `lsRemote`, how a resumed step behaves, and how to handle estimates that are wrong.

## Decision

1. **`GitClient` stays minimal.** Adapters only need `lsRemote` (ADR-0190). The richer operations live on `GitService` in `packages/git`, which the jobs runtime and the Run engine use directly. Nothing was added to the SDK interface.
2. **Quota through a one-method interface.** `GitQuota { acquire(units) }` is what the commands call. `createGitQuota` adapts the SDK's `QuotaGate.acquire` to it (bucket key, limit, window, pool) and raises `rate_limited` with `retryAt` when the grant is denied. `packages/git` therefore has no edge to `quota`. One `GitService` is built per credential, so a Run uses one credential throughout (JOB-042). Units: ls-remote 1, clone or fetch 3, each push attempt 3 (retries spend again), LFS 1 per 100 objects not yet transferred.
3. **Askpass confined to one origin.** The generated script checks that the prompt names the origin of the URL the command was started for (git quotes with `'`, git-lfs with `"`), and gives nothing otherwise. The username and password are two lines of a 0600 file; nothing secret is in the script, argv, URLs, `.git/config` or the environment. A secret in argv aborts the command. Credentials with line breaks or shorter than `MIN_SECRET_LENGTH` are refused (the scrubbers cannot remove short values).
4. **Remotes by environment.** `git lfs` needs a remote name. The mirror has `origin` (source URL, no credentials, written by `clone --mirror`). The target remote `gm-target` and `lfs.concurrenttransfers` are given through `GIT_CONFIG_COUNT` and friends, so nothing about the target is written to `.git/config`. `git lfs fetch` and `push` with a bare URL as the remote misbehaved in git-lfs 3.4 (credential fill loops), hence names.
5. **LFS parity through an injected client.** FAC-GIT-005 names the batch API `download` operation, which is HTTP to the provider. `verifyLfsParity` takes an `LfsBatchClient` that the adapter or worker builds over `ProviderHttpClient` (all provider HTTP goes through it and the quota service); the package chunks objects (at most 100 per call) and interprets answers. A 404 or a missing `download` action is "missing", other errors are "failed" (unverifiable), a response that omits a requested object is an error.
6. **Resumable steps.** `mirror` clones into `<dir>.partial` and renames, so an interrupted clone is discarded; an existing `<dir>` is fetched (`+refs/*:refs/*`, prune). `fetchLfs` counts only objects not yet downloaded. `pushRefs` lists the target first, skips refs already at the wanted sha and excludes shas the target has from every estimate.
7. **Which refs.** Only `refs/heads/*` and `refs/tags/*` are pushed and scanned. Hidden refs (pull request refs and the like) stay in the mirror, because the target rejects them. `git push` is never `--mirror` and never `--atomic`.
8. **Estimator and adaptivity.** The default estimator is `rev-list --objects --disk-usage --stdin` when git is 2.31 or later, otherwise `pack-objects --revs --stdout --thin` counted without buffering. Checkpoints are found by binary search on the first-parent list. Because the estimate is only an estimate, a `push-too-large` rejection of a multi-commit push halves the target size and plans again; a rejected group is split; only a single commit or tag that is rejected alone surfaces `push-too-large` (LIF-042). A caller or test may pass its own estimator function.
9. **Retries.** Pushes retry up to 3 times with full-jitter exponential backoff (base 1 s, cap 60 s, ADP-060) for failures classed retryable (network, 5xx, unknown). `rate_limited`, authentication, not found, hook rejections and size rejections are not retried in process.
10. **JOB-015.** T-028 owns scratch directories and the disk precheck. The git package exposes `mirror().sizeBytes` and `lfsBytes()` for the size inputs and duplicates nothing.
11. **Blob scan.** `git rev-list --objects --branches --tags` piped into `git cat-file --batch-check` (no per-object process, constant memory). Blockers are blobs larger than the target's `maxBlobBytes`, warnings are blobs larger than 50 MiB up to the limit; both carry `path`, `size`, `oid` and the exceeded `limit`. Findings are sorted by size. Paths containing a newline are not representable in this protocol and are reported by object id.
12. **`deleteRefs`** (groups of 100, forced) is provided for the `adoptNonEmpty` reconcile of LIF-043; the engine decides which refs to delete.
13. **LFS endpoint pinned.** A `.lfsconfig` committed in a source repository can set `lfs.url` and redirect LFS fetch and push to another repository. Every LFS command therefore gets `lfs.url`, `lfs.pushurl`, `remote.<name>.lfsurl`, `remote.<name>.lfspushurl` (all `<remote url>/info/lfs`) and `lfs.<url>.locksverify=false` through command-scope `GIT_CONFIG_*`, which beats `.lfsconfig`. Turning lock verification off also removes a call that quota does not count.
14. **Push rejections.** `git push --porcelain` reports per-ref results on stdout; stderr only says "failed to push some refs". Lines starting with `!` make the failure a non-retryable `conflict` (`reason: rejected`) whose message names the refs and reasons, unless stderr names a more specific cause (size, authentication, rate limit). Invalid refspecs are `invalid`. The retry loop therefore does not repeat a rejection.
15. **Stalled remotes.** `http.lowSpeedLimit=1000`, `http.lowSpeedTime=60` and the `lfs.*timeout` settings are set in the environment, and remote commands run in their own process group under an inactivity watchdog (default 10 minutes without stdout or stderr output; `stallTimeoutMs`). A stall kills the group and raises a retryable `transient` error. Clone, fetch and push use `--progress` and git-lfs `GIT_LFS_FORCE_PROGRESS=1` so long transfers keep producing output. Commands that only read the mirror (estimates, ref lists) run with a credential-free context and no watchdog.
16. **Origin matching.** URLs are normalised with `new URL(u).href` before they reach git, so the origin in git's prompt equals the one the askpass script checks.
17. **JOB-015 estimate.** `scratchNeededBytes({ sizeBytes, lfsBytes })` is `ceil(sizeBytes x 2.2) + lfsBytes` in integer arithmetic. T-028's `checkScratchSpace` consumes it; the delay and the counter stay there.
18. **Stale credentials.** Askpass directories are named `.gm-askpass-<uuid>` inside the scratch directory. The process keeps a registry of the sessions it has open; `sweepStaleCredentialFiles(dir)` removes a `.gm-askpass-*` directory only when it is not in that registry and is older than `olderThanMs` (default 10 minutes), so a long-running command keeps its credential and only directories a SIGKILL orphaned are removed. This relies on the scratch volume being per worker pod (JOB-015 `emptyDir`): a volume shared between processes would need owner tokens in the directory instead, because one process cannot see another's registry. T-028's scratch cleanup should call the sweep.
19. **`deleteRefs` input.** Names must be under `refs/heads/` or `refs/tags/`, valid by git's refname rules (`isValidRefName` is a port of `git check-ref-format`, tested against the real command, so `+`, `@` and non-ASCII characters inside a name are accepted), and not under `refs/heads/git-migrator/`. Globs, `:` and a leading `+` are refused by the same rules. The check runs before any push.
20. **Cancellation.** The abort signal is not handed to `spawn` (that would kill only the leader). The executor kills the whole process group, the same path as a stall, and the runner raises `GitCommandError` with `code: transient`, `reason: cancelled`, `retryable: false`; a raw `AbortError` never escapes and the push retry loop does not retry it.
21. **Decoding.** stdout and stderr are decoded with a stateful `StringDecoder`, because ref names and paths can span chunk boundaries.
22. **Classification inputs.** Before classifying, URLs are replaced and the refspec column of porcelain lines is dropped, so repository and branch names cannot imitate error text; provider codes are anchored and case-sensitive (`error: GH001`). A `[remote failure]` status, or network text in stderr, is retryable and beats a generic rejection line.
23. **`lfs.allowincompletepush=false`** is pinned with the other LFS settings, so a `.lfsconfig` cannot let a push succeed while objects are missing.

## Alternatives

- Credentials in `http.extraHeader` through `GIT_CONFIG_*`: works with the fake, but puts a reusable Authorization header into every request including redirects to other hosts, and into the environment of git-lfs' children. Rejected for the spec's askpass.
- Git credential helper reading the environment: the secret would sit in the environment. Rejected.
- Importing `quota` into `packages/git`: rejected by ARC-012 (`git` depends on `adapter-sdk`, `core`, `canonical`).
- Adding all operations to the SDK `GitClient`: would make every adapter test double larger for no adapter use.
- Pushing the default branch with one `git push` and relying on provider limits: violates LIF-044.

## Consequences

The Run engine (T-0xx) calls `GitService` directly for steps 2, 4 and 5 and builds the `LfsBatchClient` for step 13. The worker constructs one `GitService` per credential with `createGitQuota`. Live runs should confirm the stderr fragments used for classification (ADR-0071 follow-up) and the unit of `repository.size` (ADR-0036).
